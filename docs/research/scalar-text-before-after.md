Baseline: `767321b122080991929dde50382d663dc306ac17` (PR #19 merge). Upstream:
`df4ceba5e08220db670c25afead342ce699c50b5`, `Features.PowerFxV1`, en-US, UTC. Both profiles ran

[`scalar-text-before-after.cases.tsv`](scalar-text-before-after.cases.tsv).

resolvable with the scalar functions. The detailed TSV preserves every corpus line and verdict
transition. Table overloads of `Len`, `Lower`, and `Upper` remain unsupported; the implementation
does not add table lifting, `Text` formatting, new formula types, or locale support.

## Probe and runtime evidence

Both-mode reference probes are generated before implementation from
`docs/research/scalar-text-probes/expressions.txt` and replayed from
`packages/engine/test/fixtures/scalar-text-probe.*.tsv`. They cover supported scalar coercions,
Blank and reached Error behavior, diagnostics and arities, UTF-16 code-unit length, and reference
en-US casing for Turkish I variants, Greek sigma, non-expanding mappings, supplementary Deseret
letters, and emoji. A test additionally verifies that an unpaired UTF-16 surrogate is preserved.

The frozen casing table was generated by the harness from installed .NET en-US `TextInfo` behavior
and exhaustively checked against that reference for every Unicode scalar value. Its runtime and
provider caveats, exact commands, and pinned source paths are in
[`scalar-text-probes/README.md`](scalar-text-probes/README.md). These results establish parity for
the tested slice and corpus, not language completeness or a completion percentage.
